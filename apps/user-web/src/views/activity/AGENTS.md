# 活动页面模块说明

## 模块简介

`src/views/activity/` 提供用户端活动入口、活动首页、聊天室和个人页，并由 `index.vue` 承接活动级认证状态与底部导航。

## 主要职责

- 加载活动公开信息并承载手机号验证码登录和活动用户会话。
- 根据命名路由渲染首页、抽奖控制、聊天和“我的”页面。
- 聊天页负责历史消息、WebSocket 实时消息、表情包和发送交互。
- 在移动端处理安全区、软键盘和可视视口变化，保持聊天输入区可用。

## 目录说明

- `index.vue`：活动壳、登录流程、活动会话和底部 Tabbar。
- `chat.vue`、`chat.css`：聊天消息列表、输入区、表情选择器和 WebSocket 生命周期。
- `useKeyboardViewport.ts`：聊天路由的软键盘状态与 `visualViewport` 尺寸监听。
- `home.vue`、`lottery-results.vue`、`lottery.vue`、`me.vue`：活动首页、抽奖活动查看页、抽奖控制页和当前用户信息页。
- `activity.css`、`activity-auth.css`、`lottery-results.css`：活动壳、导航、公共页面、认证页和抽奖查看页样式。
- `session.ts`：活动壳向子页面提供登出能力的注入契约。

## 核心流程

活动壳加载活动和当前活动用户后渲染子路由。未登录时先通过手机号发送验证码；短信核验成功后，已有用户直接建立活动会话，
新用户在同一认证页补充姓名后再完成创建。进入聊天路由时，视口组合函数记录未弹键盘时的基准高度并监听输入框焦点、
窗口及 `visualViewport` 事件；可视高度减少超过键盘阈值时隐藏 Tabbar，恢复后显示。输入框聚焦不覆盖基准高度，避免
iOS/WebView 在 `focusin` 与视口变化顺序不同导致状态识别失败；触屏 WebView 缺少视口事件时由焦点延迟兜底。聊天内容
使用可视视口高度、导航高度和安全区变量计算；键盘态活动页固定在可视视口内并锁定文档滚动，使消息区和输入栏作为
同一聊天窗口一起调整。输入框聚焦或键盘视口变化后，消息区等待两帧布局完成再滚动到底部；键盘回落时恢复键盘前的
视口高度、重置文档滚动位置，并在消息列表高度恢复后再次滚动到底部。消息区独立滚动，输入栏保持固定触控按钮尺寸。

## 依赖关系

模块依赖 `api/client.ts` 的活动、聊天、移动端抽奖和媒体接口，使用 Vue Router、Vue 组合式 API 及 Vant 4 移动端组件。

活动首页的“活动服务”列表展示抽奖活动查看页和聊天室，并在用户具备 `can_mobile_lottery` 权限时追加抽奖控制页；
首页本身通过底部导航进入，不在服务列表中重复展示。抽奖活动查看页通过公开 lottery WebSocket 实时接收启用奖品、库存和中奖结果，
轮播当前奖品时同步展示该奖品的全部中奖人。

抽奖控制页只读取管理端已配置的启用奖品和实时库存；切换奖品与直接开奖分别调用受保护接口，切换会同步活动级当前奖品，开奖结果由后端复用现有资格规则并同步管理员和大屏。

## 注意事项

- 聊天高度必须继续使用可视视口变量，不能只依赖固定 `100dvh`。
- 键盘显示期间不要恢复 Tabbar 或重复添加底部安全区，否则输入栏会被键盘遮挡。
- 键盘态必须锁定根文档滚动并让活动页固定到可视视口，不能只依赖焦点元素的原生自动滚动。
- 不要在 `focusin` 时重置键盘基准；键盘可能已经在焦点事件前缩小视口。
- 键盘关闭应等待输入失焦或视口恢复，避免键盘动画中间帧提前显示 Tabbar。
- 键盘打开会缩小消息列表的可视高度，必须在布局更新后重新设置列表滚动位置，不能依赖浏览器自动保留原 `scrollTop`。
- 键盘回落后必须恢复键盘前的视口高度，并将 `window`、`html`、`body` 滚动位置归零，避免 iOS 页面底部留下空白。
- 消息列表高度恢复后还要重新校正内部 `scrollTop`，否则键盘态旧滚动位置会在最后一条消息与输入栏之间留下空隙。
- `visualViewport.scale` 变化代表缩放，不应单独触发键盘状态。
- 修改聊天输入区后需要检查 320px 至 430px 宽度下的发送按钮和横向溢出。
