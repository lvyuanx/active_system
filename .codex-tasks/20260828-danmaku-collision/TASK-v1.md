# TASK-v1：B站式弹幕碰撞避让

## 目标

将弹幕投屏器当前“每条弹幕占用轨道至完整飞行时长”的调度方式，改为按弹幕实际宽度和运动轨迹预测碰撞；在不发生重叠时允许同一轨道提前进入下一条弹幕，减少投屏画面的空旷感。

新增可持久化的最大等待时间配置，默认 1.5 秒，由管理端设置并实时同步到已连接投屏器。

## 用户场景

1. 管理员在活动“弹幕工具”页面设置最大等待时间并保存，已连接投屏器即时收到新配置。
2. 两条短弹幕在同一轨道上有足够间距时，后一条在前一条完全出屏前进入。
3. 长弹幕可能追上同轨道前一条弹幕时，渲染器暂不放入该轨道，优先尝试其他轨道。
4. 所有轨道暂时都不安全时，弹幕最多等待配置时长，过期后丢弃，避免延迟消息集中追赶。

## 范围

- 后端 `activity_danmaku_settings` 增加 `max_wait_seconds`，兼容旧 SQLite 数据库并保留旧客户端提交能力。
- 管理端、screen-web 和 Electron 会话类型同步新字段。
- screen-web 新增无浏览器依赖的弹幕运动矩形和碰撞判断模块。
- 渲染器采用固定 8px 最小水平间距和轮询轨道选择；保留 CSS transform 位移动画及现有 200 条有界队列。
- 补充后端迁移/接口测试、碰撞几何测试、静态回归和构建验证。
- 同步受影响模块 AGENTS、MEMORY、LEARNING、WIKI 及本次任务证据。

## 非目标

- 不新增“正常/较密/允许重叠”模式。
- 不实现智能防挡、人像蒙版、Canvas/WebGL 重构或高级弹幕。
- 不修改 WebSocket 消息字段、token、聊天室协议、多屏窗口和活动生命周期。
- 不清理或回写既有聊天/弹幕数据。

## 约束与默认值

- `max_wait_seconds` 是浮点数，范围 `0.5–5.0`，管理端步长 `0.1`，默认 `1.5`。
- 等待时间从消息进入渲染器本地队列时开始计算，不使用服务器 `created_at`。
- 碰撞判断使用文本测量宽度、当前视口宽度、统一飞行时长和固定 8px 间距。
- 当前正在显示的弹幕保留其原有样式/轨迹；配置更新只影响新入场弹幕。
- 当前工作树已有未提交弹幕相关改动，按输入快照保留，不回退无关变更。

## 验收标准

- AC-001：新活动默认返回 `max_wait_seconds = 1.5`；旧数据库初始化后自动增加字段且旧配置可读取。
- AC-002：`0.5`、`1.5`、`5.0` 保存成功；范围外值返回 HTTP 422；缺少新字段的旧客户端更新请求仍可成功。
- AC-003：管理端保存回包和 `danmaku.settings.updated` 广播均包含新字段，投屏器可实时应用。
- AC-004：同轨道两条不碰撞弹幕可在前一条出屏前入场，并保持至少 8px 水平间距。
- AC-005：长弹幕追赶短弹幕或当前入场会重叠时，当前轨道被判定为不可用并尝试其他轨道。
- AC-006：所有轨道不可用时，消息按 FIFO 等待；超过 `max_wait_seconds` 后丢弃，不改变后续消息顺序。
- AC-007：队列仍最多保留 200 条，轮询轨道选择避免连续偏向第一条轨道，生命周期任务仍由统一帧调度器管理。
- AC-008：配置更新不清空当前弹幕，不留下旧调度任务，不产生重复渲染；断线补齐、重连和多屏行为保持回归通过。
- AC-009：相关模块文档、项目知识和 TaskGraph/交接证据与实现一致，后端全量测试、前端类型检查和构建通过。

## 风险、回滚与待确认项

- 风险：浏览器 Canvas 文本测量与实际字体回退可能产生少量宽度误差；实现保留 8px 安全间距并使用保守碰撞判断。
- 风险：SQLite 旧表加列属于只增量迁移；迁移失败由现有事务回滚，代码回滚不执行破坏性删列。
- 回滚：恢复旧调度代码即可停止新碰撞算法；保留新增数据库列以维持数据兼容，不删除已保存配置。
- 待确认项：无。范围、等待策略、等待时长范围和不新增密度模式均已确认。
