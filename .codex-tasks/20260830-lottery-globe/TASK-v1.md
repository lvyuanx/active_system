# TASK-v1：抽奖球体动画与开始/停止开奖

任务等级：T6（跨后端、管理端和公开大屏；涉及权限、SQLite 并发、幂等、实时协议和高回滚风险）

## 目标

将既有即时开奖改为“开始抽奖 → 持续滚动 → 停止抽奖 → 事务开奖”的两阶段流程。大屏在开始时冻结并展示全部活动用户，
使用 Canvas 3D 球体持续旋转；后端停止并提交中奖记录后，大屏减速并把中奖用户居中揭晓。页面占满视口且不产生文档滚动。

## 范围

- 后端增加活动级单进程内存轮次，冻结开始时全部活动用户和当时合资格用户 ID。
- 增加 `lottery.draw.start`、`lottery.draw.started`、`lottery.draw.stop` 协议；保留旧 `lottery.draw.request` 兼容处理。
- 停止阶段沿用 `BEGIN IMMEDIATE` 事务、库存和资格复核，以轮次 ID作为开奖 `request_id`，提交后才广播结果。
- 轮次期间锁定奖品配置、图片、黑白名单和重置，并通过 `lottery.ready.active_round` 支持管理端/大屏恢复。
- 管理端增加 idle/starting/rolling/stopping 控制状态、多窗口同步和按钮/表单锁定。
- 大屏增加 Fibonacci 球面、透视投影、深度透明度、头像映射、减速居中、空名单/缺失布局/重复事件/断线恢复处理。
- 同步 lottery 模块文档、项目知识、测试和交接证据。

## 非目标

- 不新增轮次数据库表；后端重启时未完成的内存轮次取消。
- 不新增 Fullscreen API 按钮；“全屏”仅指浏览器或 Electron 视口布局。
- 不把候选资格、手机号、名单标记、停用状态或管理员字段发送给公开大屏。
- 不实现多副本共享消息总线；当前连接管理器保持单进程能力。

## 验收标准

- AC-001：给定任意支持的屏幕尺寸，大屏根节点、`document` 和 `body` 占满视口且横向/纵向滚动范围等于视口。
- AC-002：开始消息只启动动画，不产生中奖记录；开始事件包含开始时全部活动用户的 `activity_user_id`、用户名和头像 ID。
- AC-003：开始后球体持续旋转；管理端按钮显示“停止抽奖”，停止后才触发后端选人。
- AC-004：停止开奖在 `BEGIN IMMEDIATE` 中复核库存和资格，提交成功后才广播管理员结果及公开 `lottery.drawn`。
- AC-005：开始后新增用户不进入轮次；停止时冻结候选池中的用户仍需复核有效状态；活动和奖品隔离保持不变。
- AC-006：轮次期间配置、奖品图片、黑白名单和重置均被前端锁定且由后端返回冲突；库存不超发。
- AC-007：同轮次重复停止最多产生一条记录，重复请求返回已有结果且不重复广播大屏揭晓动画。
- AC-008：多个管理端和大屏在 `lottery.ready` 中恢复 `active_round`，断线重连和重复事件不重复揭晓。
- AC-009：公开事件不包含手机号、黑白名单、停用状态、候选资格、管理员字段或存储 key；旧协议仍可用。
- AC-010：Canvas 球体使用本地 20 个头像资源；停止后中奖者约 2 秒减速并位于中心，缺失本地布局时仍能显示用户名和默认头像。
- AC-011：后端全量测试、screen-web 测试、两端类型检查和生产构建通过，模块文档与项目知识同步。

## 风险、回滚与运行证据

- 风险：轮次状态为单进程内存，服务重启会取消未完成动画；多副本仍需共享消息总线。
- 回滚：移除 start/stop 协议消费和球体组件即可恢复旧客户端；已落库中奖记录不因代码回滚删除。
- 运行证据：保留后端 pytest、前端 test/typecheck/build、`compileall`、`git diff --check`、安全字段断言和浏览器流程 DOM/截图结果。

待确认项：无。奖项、奖品、名单规则和真实中奖资格沿用既有实现。
