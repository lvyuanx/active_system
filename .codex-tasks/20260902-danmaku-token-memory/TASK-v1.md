# TASK-v1：固定活动弹幕 token 并记住桌面工具 token

任务等级：T4（活动弹幕与桌面工具的单模块行为变更，不改变既有管理员接口协议）

## 目标

- 活动创建完成时即初始化活动级弹幕 token 记录。
- 弹幕 token 在播放设置保存、活动状态变化和服务重启后保持不变，仅手动调用 token 刷新接口才轮换。
- 弹幕桌面工具在成功启动后通过 Electron `safeStorage` 加密记住最近一次 token，下次打开启动页时自动填充。

## 用户场景

- 管理员创建活动后，进入弹幕工具页多次读取或保存播放设置，看到的 token 始终相同。
- 管理员明确点击“重新生成 token”后，旧 token 失效，新 token 返回并成为后续唯一有效 token。
- 管理员在桌面工具中成功启动一次弹幕后关闭工具，再次打开启动页时，token 输入框默认带出上次成功使用的 token。
- 桌面工具只在系统安全存储可用时持久化加密数据；不会将 token 写入浏览器 `localStorage`、日志或明文配置。

## 范围

- 调整活动创建与弹幕默认记录初始化的数据流。
- 调整 `apps/danmaku-desktop` 启动页、预加载桥和主进程的 token 记忆流程。
- 增加后端 token 生命周期回归测试和桌面端安全存储/启动页静态与行为测试。
- 同步后端弹幕模块、桌面工具模块和项目知识文档。

## 非目标

- 不修改弹幕 token 的字符串格式、HMAC 算法、活动隔离规则或手动轮换接口。
- 不改变弹幕 WebSocket、历史消息、播放设置或测试弹幕行为。
- 不保存 API 地址，不把 token 同步到管理端浏览器本地存储。
- 不引入新的第三方凭据存储依赖。

## 约束

- `activity_danmaku_settings` 仍以 `activity_id` 为主键；新活动使用 `token_version=1`。
- 既有旧数据库中的活动继续支持按需补齐缺失弹幕记录。
- 只有管理员手动调用 `/admin/activities/{activity_id}/danmaku/token` 才递增 token 版本。
- 桌面端 token 持久化使用 Electron `safeStorage`，持久化内容只能是加密后的字节。
- 启动页只记住最近一次服务端校验成功的 token；无效输入不能覆盖已记住的 token。

## 验收标准

### AC-001：创建活动即固定 token

Given 管理员创建一个新活动
When 活动创建事务提交
Then 该活动已有默认弹幕记录和初始 token 版本，首次读取弹幕设置不会重新生成 token。

### AC-002：非手动操作不轮换

Given 活动已有 token
When 重复读取弹幕配置、保存播放设置、切换活动状态或重启服务
Then token 字符串和 `token_created_at` 保持不变，旧 token 仍可建立弹幕会话。

### AC-003：手动刷新才轮换

Given 活动已有有效 token
When 管理员明确调用 token 刷新入口
Then 返回新 token，旧 token 失效，且已有弹幕连接按既有行为断开。

### AC-004：桌面工具记住最近成功 token

Given 桌面工具使用 token 成功启动弹幕
When 再次打开启动页
Then token 输入框默认填充最近一次成功使用的 token；API 地址和显示器选择继续使用既有默认/运行时行为。

### AC-005：安全存储与回归验证

Given 桌面端安全存储可用或不可用
When 执行保存、读取和启动页初始化
Then 可用时只保存加密字节并正确恢复，不可用时安全降级且不写明文；后端测试、桌面端类型检查和 token 测试通过。

### AC-006：文档同步

Given 实现完成
When 检查受影响模块说明和项目知识
Then 文档准确描述活动创建初始化、手动轮换边界和桌面端安全记忆流程。

## 风险、依赖与待确认

- Electron `safeStorage` 在 Windows 目标环境中可用；不可用时只能安全降级为本次运行内存，不得退回明文持久化。
- 旧活动记录仍由弹幕服务的兼容逻辑懒补齐，不能影响既有数据库启动。
- 待确认项：无；任务单进入开发阶段后冻结。
