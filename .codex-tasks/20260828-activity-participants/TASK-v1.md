# TASK-v1：管理端参与者管理

任务等级：T6（活动用户数据迁移与会话安全行为）

## 目标

为单个活动提供超级管理员参与者列表，支持持久禁言/解除禁言、停用/恢复，并让停用期间的活动用户会话失效。

## 范围

- 新增活动参与者管理员 API 和管理端页面。
- `activity_users` 增加 active、muted 和会话版本状态，并支持旧数据库增量迁移。
- 禁言用户可以登录和查看聊天，但不能发送消息。
- 停用用户不能登录、访问活动身份接口或发送聊天消息；恢复后必须重新登录。

## 非目标

- 不增加参与者密码字段或重置密码功能。
- 不增加参与者搜索、分页、批量操作或删除。

## 验收标准

- AC-001：给定超级管理员打开某活动的管理页，访问参与者入口时，页面展示该活动全部参与用户及用户名、手机号、加入时间和当前状态。
- AC-002：给定用户处于正常状态，管理员执行禁言后，该用户仍可登录和读取聊天，但发送消息返回 `chat.error`/`muted` 且不产生聊天记录；解除禁言后可恢复发送。
- AC-003：给定用户处于正常状态，管理员执行停用后，该用户登录、`/me`、聊天历史和 WebSocket 鉴权均被拒绝；已有 WebSocket 下一次发送返回未授权并关闭。
- AC-004：给定用户已停用，管理员恢复该用户后，停用前旧 token 仍不可用，使用原用户名和手机号重新登录取得的新 token 可用。
- AC-005：给定两个活动，任何参与者列表和状态操作均只影响 URL 指定活动；跨活动用户 ID、无效活动和未授权请求均被拒绝。
- AC-006：给定旧版 `activity_users` 表，数据库初始化后新增字段默认值为 active、未禁言和会话版本 0，旧 token 在未发生停用前保持兼容。
- AC-007：给定管理端页面，侧边栏参与者入口可导航到受保护路由；状态操作有确认、加载锁定、成功/失败反馈，并通过管理端类型检查和生产构建。

## 约束

- 活动隔离必须通过 `activity_id` 同时作用于读取和写入。
- 停用通过递增会话版本撤销 token；重复停用不得重复递增版本。
- 活动聊天历史保留，停用/禁言不删除历史记录。

## 风险与回滚

- 风险：旧活动用户表需要启动时增量增加状态字段；会话版本校验会使已停用用户的旧 token 失效。
- 回滚：代码回滚前保留新增字段不会影响旧查询；如需恢复旧行为，只能回滚应用并重新部署，不能恢复已被撤销的会话 token。
- 运行证据：需要保留后端完整测试、全仓前端类型检查/构建、`git diff --check` 及管理端页面加载验证结果。
