# TASK-v1：实时抽奖特殊配置安全码

任务级别：T6

## 目标

将管理端实时抽奖配置中的“配置黑白名单”入口改为“特殊配置”。管理员必须输入后端配置的安全码并通过服务端校验后，才能打开原有抽奖名单弹窗。

## 范围

- 增加后端 `LOTTERY_SECURITY_CODE` 配置项，沿用项目 `.env` 配置方式。
- 增加仅限超级用户的实时抽奖安全码校验接口；安全码不得出现在响应或前端构建产物中。
- 管理端使用密码式输入框验证安全码，校验成功后打开原有黑白名单配置弹窗。
- 保持名单搜索、筛选、分页和黑白名单更新语义不变。
- 同步 `.env.example`、README、模块说明、项目知识和任务证据。

## 非目标

- 不改变抽奖资格计算、名单接口字段、黑白名单互斥规则或 WebSocket 协议。
- 不把安全码写入前端环境变量、浏览器存储、日志或数据库。
- 不新增安全码修改页面、失败次数锁定或跨活动权限模型。

## 约束、风险与回滚

- 安全码只从后端 `Settings` 读取，比较使用常量时间比较；未配置时拒绝验证并提示运维配置。
- 新增接口必须继续要求超级用户 JWT，并校验活动上下文。
- 旧客户端仍可调用原有名单接口；本次改动只增加管理端入口校验，避免破坏既有 API 兼容性。
- 如前端验证流程或后端接口出现问题，可回滚本次新增配置、接口和入口调用，原名单弹窗及名单 API 仍保持可用。

## 验收标准

### AC-001

Given 后端配置了 `LOTTERY_SECURITY_CODE` 且管理员已登录实时抽奖页面。

When 管理员点击“特殊配置”并输入正确安全码。

Then 服务端校验成功，原有抽奖名单弹窗打开。

### AC-002

Given 管理员点击“特殊配置”。

When 输入错误或空安全码，或取消输入。

Then 抽奖名单弹窗不打开；错误信息清晰，安全码不被回显或返回。

### AC-003

Given `LOTTERY_SECURITY_CODE` 未配置、请求未认证或活动不存在。

When 请求安全码校验接口。

Then 服务端拒绝请求并返回对应错误，不泄露配置值；已有名单数据和资格规则不受影响。

### AC-004

Given 本次代码与文档已完成。

When 执行后端安全码回归、管理端类型检查/构建和差异检查。

Then 所有阻断验证通过，且任务变更文件未超出冻结范围。
