# TASK-v1：弹幕完整进入后间隔入场

## 目标

将弹幕同轨道的再次入场条件从“上一条完全离屏”改为“上一条完整进入视口后，经过可配置间隔即可尝试入场”，同时保留不重叠和长弹幕追赶保护。

## 已确认规则

- 完整进入：弹幕右边界越过视口右边界，整条文字已经显示在屏幕内。
- 新增 `entry_interval_seconds`，默认 1.0 秒，范围 0.1–5.0 秒，管理端步长 0.1 秒。
- 间隔只约束同一轨道；不同轨道可以立即入场。
- 碰撞预测仍然生效；长弹幕会追赶时换轨，所有轨道不可用才进入队列。
- 现有 `max_wait_seconds` 保持为拥堵队列最大等待时间，默认 1.5 秒，独立于入场间隔。

## 范围与非目标

- 更新 SQLite schema/旧库迁移、后端模型和设置回包，管理端控件及三端类型。
- 更新 screen-web 几何函数和渲染调度，保留 CSS transform、统一帧调度、200 条 FIFO 队列、重连和多屏协议。
- 不新增密度模式，不允许明显重叠，不修改 token、聊天消息字段或 WebSocket 消息类型。

## 验收标准

- AC-001：新字段默认返回 1.0；旧 SQLite 启动时自动增加字段。
- AC-002：0.1、1.0、5.0 保存成功；范围外值返回 422；旧请求体省略新字段仍成功。
- AC-003：HTTP 回包及既有 `danmaku.ready`/`danmaku.settings.updated` 携带新字段。
- AC-004：同轨道在完整进入前不能再次入场；完整进入后经过配置间隔即可尝试入场，且上一条仍可在屏内。
- AC-005：不同轨道不受该间隔限制；长文本追赶时跳过冲突轨道。
- AC-006：所有轨道不可用时按 FIFO 等待，超过 `max_wait_seconds` 丢弃队首。
- AC-007：保留 200 条队列上限、50ms 重试和统一调度器，不恢复逐条定时器。
- AC-008：设置更新不改变当前弹幕轨迹；新设置影响后续入场，重连/补齐/多屏行为保持。
- AC-009：相关文档同步；后端测试、前端测试、类型检查、构建和 Windows x64 打包通过。

## 风险与回滚

- 文本宽度受字体回退影响，使用实际 Canvas 测量和保守碰撞判断。
- 回滚代码时保留新增数据库列，不执行破坏性删列。
- 若桌面视觉验收失败，优先检查完整进入时间公式、CSS 终点和同轨道 ready gate 的一致性。
