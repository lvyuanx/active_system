## 目标

为活动用户头像系统新增 11–20 号十款卡通 SVG，保持已有 1–10 号头像和已落库头像不变；新注册用户从完整的 1–20 号头像池中随机获得头像。

## 范围

- 新增 `avatar-11.svg` 至 `avatar-20.svg`，资源为纯静态、本地、可渲染 SVG。
- 后端随机分配和响应校验范围扩展到 1–20。
- 前端类型与静态资源映射扩展到 20 款。
- 更新相关测试、模块说明和项目知识文档。

## 非目标

- 不改变已有用户的 `avatar_id`。
- 不新增换头像、上传头像或后台批量迁移能力。
- 不修改聊天消息、WebSocket 或活动隔离规则。

## 验收标准

### AC-001

Given 头像资产进入验收，When 清点用户端头像目录，Then 恰好存在 20 款纯静态 SVG，新增 11–20 号资源彼此可区分且无脚本、外链或重复内容。

### AC-002

Given 新用户完成当前活动注册，When 读取注册响应、再次登录和 `/me`，Then `avatar_id` 始终属于 1–20 且已分配值保持稳定。

### AC-003

Given 已存在 1–10 号头像的用户，When 用户再次登录或访问 `/me`，Then 原头像不变；已有活动隔离和聊天回归测试继续通过。

### AC-004

Given 前端收到任一 1–20 的 `avatar_id`，When 渲染活动首页或“我的”页，Then 组件能通过本地静态映射展示对应头像。

## 验证

- 后端完整测试：`python -B -m pytest -q -p no:cacheprovider apps/backend`
- 前端类型检查：`pnpm typecheck`
- 前端构建：`pnpm build`
- SVG 静态扫描：数量、唯一性、脚本和外链检查。
