# TASK-v1：奖品级黑白名单配置

任务级别：T6

## 目标

黑名单、白名单规则改为针对具体奖品配置。同一活动中，不同奖品可以拥有独立的黑名单、白名单、名单统计和可抽奖资格。

## 范围

- 新增活动奖品级名单规则存储，并保持 `activity_id` 隔离。
- 现有活动级 `lottery_entries` 数据在首次使用奖品名单时迁移到该活动已有奖品，避免历史规则丢失；迁移后新增奖品默认无名单限制。
- 管理端“特殊配置”弹窗增加奖品选择，当前奖品的搜索、筛选、统计、黑白名单切换均只影响当前奖品。
- 开奖开始和停止时均使用当前 `prize_id` 的名单规则计算候选人。
- 同步参与者注册、抽奖模块、管理端模块说明、项目知识、测试和任务证据。

## 非目标

- 不改变活动级“跨奖品不重复中奖”规则、奖品库存、抽奖 WebSocket 消息结构或安全码校验流程。
- 不改变活动用户的停用状态；停用用户对所有奖品始终不可中奖。
- 不删除旧 `lottery_entries` 表，保留它作为一次性迁移来源；新业务不再写入该表。

## 约束、风险、回滚

- 新表以 `(activity_id, prize_id, activity_user_id)` 唯一约束，查询和更新必须同时校验活动与奖品归属。
- 旧活动级规则按迁移时已有奖品复制；迁移标记按活动记录，避免每次启动将旧规则复制到后来新增的奖品。
- 这是数据结构和开奖资格变更，必须验证旧数据库迁移、跨奖品隔离、并发/两阶段开奖和历史规则兼容。
- 回滚代码时保留新增表和迁移数据，不自动删除数据；若恢复旧版本，旧版本仍可读取原 `lottery_entries`，但新增奖品级差异需要通过前向版本继续管理。

## 验收标准

### AC-001

Given 同一活动存在至少两个奖品。

When 为奖品 A 和奖品 B 分别设置不同用户的黑名单/白名单。

Then 查询和统计只反映当前奖品，两个奖品的规则互不影响。

### AC-002

Given 管理员通过安全码打开“特殊配置”弹窗。

When 切换奖品并搜索、筛选、分页或切换名单开关。

Then 所有操作针对当前选中的奖品，切换后能看到对应奖品独立的规则状态和摘要。

### AC-003

Given 当前奖品配置了黑白名单规则并开始/停止开奖。

When 后端计算当前奖品候选池。

Then 仅应用当前 `prize_id` 的规则，同时继续应用活动停用状态和跨奖品不重复规则。

### AC-004

Given 数据库中存在升级前的活动级 `lottery_entries` 规则。

When 升级后首次访问该活动的奖品名单。

Then 旧规则迁移到升级时已有奖品且只迁移一次，之后新增奖品默认无黑白名单规则。

### AC-005

Given 本次实现和文档完成。

When 执行后端全量测试、管理端类型检查/构建、迁移检查和差异检查。

Then 所有阻断验证通过，且保留用户已有工作树变更。
