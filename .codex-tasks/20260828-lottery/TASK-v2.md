# TASK-v2：抽奖名单弹窗化与服务端分页优化

任务等级：T6（跨后端与管理端公共接口，涉及管理员权限、手机号敏感字段、事务更新和回滚风险）

## 目标

将实时抽奖页面中的全量参与者配置改为按需打开的名单弹窗，使用服务端搜索、筛选和分页，并通过单行即时保存维护黑名单与白名单，避免配置页面一次性加载或提交大量名单。

## 范围

- 抽奖配置响应改为返回名单统计，不再返回完整 `entries`。
- 新增管理员名单分页查询和单用户黑白名单更新接口。
- 使用活动隔离、管理员认证、事务更新和共享抽奖资格条件。
- 管理端增加名单配置弹窗、关键词搜索、状态筛选、分页和即时保存。
- 保留现有奖项、奖品、开奖、重置和 WebSocket 协议行为。
- 同步测试、模块 AGENTS.md、项目知识和交付证据。

## 非目标

- 不增加批量黑白名单操作。
- 不改变大屏公开 WebSocket 的消息形状和动画流程。
- 不增加多副本共享消息总线。
- 不删除历史名单数据或中奖记录。

## 验收标准

- AC-201：抽奖配置接口不返回完整名单，返回总数、可抽奖、黑名单、白名单和已停用统计。
- AC-202：名单接口支持用户名/手机号关键词、全部/可抽奖/黑名单/白名单/已停用筛选和服务端分页。
- AC-203：名单查询和更新严格校验管理员权限及 `activity_id`，不能读取或修改其他活动用户。
- AC-204：单行更新只改变目标用户，黑白名单互斥；配置奖项或奖品不会清除其他用户的名单标记。
- AC-205：管理端主页面不渲染全量名单；弹窗可搜索、筛选、翻页，切换黑白名单后即时保存并处理失败回滚。
- AC-206：现有开奖资格计算、库存、WebSocket、重置和公开字段脱敏回归通过。
- AC-207：后端测试、管理端类型检查、生产构建、差异检查和浏览器验收通过，文档与交付证据同步。

## 风险、回滚与运行证据

- 风险：配置响应字段变化、名单查询在大数据量下的查询成本、管理员可见手机号的权限边界、筛选条件与开奖资格漂移。
- 回滚：回退应用代码即可恢复旧页面；新增索引可保留；新名单更新接口产生的数据仍兼容既有 `lottery_entries` 表。
- 运行证据：保留后端完整测试、前端 typecheck/build、`git diff --check`、接口安全回归和浏览器视觉验收记录。
