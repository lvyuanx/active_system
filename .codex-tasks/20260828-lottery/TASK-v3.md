# TASK-v3：抽奖奖项与奖品树形编辑

任务等级：T4（单模块管理端行为优化，不改变后端接口和开奖协议）

## 目标

将实时抽奖配置中的奖项和奖品改为清晰的父子树形结构，先创建奖项，再在对应奖项节点下创建和编辑奖品，避免通过平铺下拉框建立错误关联。

## 范围

- 管理端奖项作为一级节点展示，奖品作为对应奖项的子节点展示。
- 新增奖品操作绑定到具体奖项；未保存奖项不能新增子奖品，并提示先保存配置。
- 保持现有奖项、奖品 HTTP 请求格式、库存约束和开奖 WebSocket 行为不变。
- 同步抽奖页面模块文档和视觉验收记录。

## 验收标准

- AC-301：页面以树形层级展示奖项及其奖品，不再要求通过奖品行下拉框选择所属奖项。
- AC-302：在某个奖项节点点击新增奖品时，子奖品只关联该奖项；未保存奖项不能新增子奖品。
- AC-303：奖项、奖品增删改后保存请求仍能正确生成现有后端格式，库存和已有中奖记录约束不变。
- AC-304：桌面端和窄屏端树形布局可读，管理端类型检查和生产构建通过。

## 实现证据

- `apps/admin-web/src/views/lottery/index.vue` 使用奖项节点包裹对应奖品节点，未保存奖项禁用新增奖品。
- `apps/admin-web/src/views/lottery/lottery.css` 提供层级连线、节点背景和窄屏布局。

## 风险与回滚

- 风险：已有平铺表单数据在树形视图中的分组、删除奖项时的子奖品状态和移动端空间布局。
- 回滚：仅回退管理端视图和样式即可恢复原编辑布局，不涉及数据库迁移。
