# TASK-v1：管理端首页增加抽奖管理入口

## 任务属性

- 等级：T4
- 状态：已被 TASK-v2 取代
- 输入版本：当前工作树（存在此前未提交的项目改动）
- 变更性质：管理端活动选择页的单模块行为与入口文案调整，不改变后端接口和抽奖协议

## 目标与用户场景

管理员登录管理端首页后，在活动卡片上可以直接进入该活动的抽奖管理页面，不需要先进入活动详情页再从侧边栏选择“实时抽奖”。该版本任务后来根据用户上下文澄清为打开公开抽奖大屏，详见 TASK-v2。

## 范围

- 在 `apps/admin-web/src/views/home/index.vue` 的活动卡片操作区增加“进入抽奖”按钮。
- 按当前活动 ID 跳转到已有的 `/activities/:activityId/lottery` 路由。
- 同步首页模块说明、管理端使用文档和项目知识/进度记录。

## 非目标

- 不新增后端接口或页面路由。
- 不改变抽奖配置、开奖控制、活动状态转换和权限逻辑。
- 不修改活动卡片点击进入活动详情的既有行为。

## 约束与风险

- 当前工作树已有此前未提交的抽奖及其它模块改动，不能回退、清理或覆盖无关文件。
- 按钮位于卡片 footer 的事件隔离区域，点击后必须只执行抽奖路由跳转，不能同时触发卡片详情跳转。
- 已关闭和已结束活动也允许进入抽奖管理页；是否允许实际开奖继续由现有抽奖页活动状态控制。

## 验收标准

### AC-001：活动卡片提供抽奖入口

**Given** 管理员已登录首页且存在活动卡片
**When** 查看任一活动卡片操作区
**Then** 可以看到“进入抽奖”按钮，且按钮不依赖活动状态隐藏。

### AC-002：按钮跳转到对应活动抽奖页

**Given** 活动卡片的活动 ID 为 `activityId`
**When** 点击“进入抽奖”按钮
**Then** 管理端跳转到 `/activities/activityId/lottery`，并且不会先跳转到活动详情首页。

### AC-003：既有行为和构建无回归

**Given** 首页仍使用卡片整体点击和底部状态操作
**When** 执行管理端类型检查与生产构建
**Then** 两项检查通过，卡片点击、开启/关闭/结束操作和现有抽奖路由保持不变。

`apps/admin-web/src/views/home/index.vue`、`apps/admin-web/src/views/home/AGENTS.md`、`apps/admin-web/AGENTS.md`、`README.md`、`MEMORY.md`、`WIKI.md`，以及本任务目录中的交接证据。
