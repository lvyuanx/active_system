# TASK-v1：抽奖球体停止后的中心放大揭晓

任务级别：T4

## 目标

优化大屏抽奖停止后的视觉链路，让现场观众清晰感知“停止旋转—球体向外打散—中奖者聚焦中心并放大—中奖卡片揭晓”。

## 范围

- 保持大屏现有 `rolling → scattering → scattered → selecting → revealed` 阶段顺序。
- 保留中奖者从打散位置向舞台中心移动的 Canvas 聚焦动画。
- 增强聚焦阶段的中心用户放大、聚光和姓名可读性。
- 将聚焦阶段文案明确为“中奖者正在中心放大”。
- 聚焦完成后继续显示中心中奖卡片。
- 同步更新抽奖组件说明、项目知识和验证证据。

## 非目标

- 不新增大屏端停止按钮或开奖控制。
- 不修改 WebSocket 协议、后端开奖算法、库存、重连、重置和历史结果逻辑。
- 不新增音效、第三方 3D 依赖或独立粒子爆炸系统。
- 不改变奖品进度板及其他非本动画区域。

## 约束、风险与依赖

- 大屏继续使用公开只读 WebSocket，仅展示安全公开字段。
- 动画必须绑定当前 `activity_id`/`round_id`，开奖结果提前到达时不得跳过打散阶段。
- `prefers-reduced-motion` 下缩短动效但保留阶段语义和最终揭晓。
- 依赖管理端发送停止请求、后端广播匹配轮次的 stopping/drawn 事件。
- 主要风险是 Canvas 与中心揭晓层的时序、长用户名布局及高人数渲染性能，需要类型、构建和浏览器验证。

## 验收标准

### AC-001

Given 大屏已收到当前轮次的 `lottery.draw.started` 并处于 `rolling`。

When 管理员点击停止且大屏收到相同 `round_id` 的 `lottery.draw.stopping`。

Then 大屏进入 `scattering`，球体停止旋转并向外打散；打散期间不显示中奖用户或卡片，完成后进入 `scattered`，提前到达的开奖结果不得跳过该阶段。

### AC-002

Given 当前轮次已进入 `scattered` 并收到相同 `round_id` 的 `lottery.drawn`。

When 大屏开始中奖者聚焦动画。

Then 中奖用户从打散位置连续移动到球体舞台中心并明显放大，中心光环/聚光和姓名清晰可见；其他参与者同步弱化，不能出现第二个中心中奖者，其他轮次不得触发聚焦。

### AC-003

Given 中奖者聚焦动画完成且当前轮次未被重置、报错或切换。

When 大屏进入 `revealed` 阶段。

Then 中心中奖卡片由较小状态放大至稳定状态，位于球体舞台中心，姓名与公开开奖结果一致，并保持到下一轮或重置。
