# TASK-v2：活动聊天室微信式 UI 与短屏布局修复

## 状态

- 等级：T2
- 状态：已冻结
- 产品门禁：completed
- 输入版本：TASK-v1 与用户新增“聊天界面 UI 要类似微信”需求
- 旧版本处理：TASK-v1 的下游测试、审核和验收结论失效
- 待确认项：无业务取舍；发送者头像数据来源需在开发阶段核验

## 目标与用户场景

- 使聊天界面具备微信式消息行结构：头像、用户名、气泡和左右方向清晰表达发送者。
- 短屏下输入区始终位于底部导航上方且完整可见。
- 保留输入沉底、默认一行且最多三行、接近底部才自动滚动、历史阅读不被打断和当前用户身份可见。

用户在 390×450 短屏中仍能看到身份、输入框和发送按钮；来消息显示左侧头像和用户名，本人消息显示右侧头像和用户名；停留在底部时实时消息自动跟随，阅读历史时不被强制拉到底部。

## 范围

- `apps/user-web/src/views/activity/chat.vue`：消息行展示、身份提示、输入区和滚动行为。
- `apps/user-web/src/views/activity/activity.css`：短屏布局、消息行、气泡和左右对齐样式。
- `apps/user-web/AGENTS.md`：同步记录聊天消息展示发送者头像和用户名的新行为。
- 复用现有活动用户身份、固定本地头像资源和安全映射能力。

## 非目标

- 不修改聊天 HTTP API、WebSocket 地址、认证方式、事件类型或消息 payload。
- 不新增后端接口、数据表、消息字段、头像选择流程或头像资源。
- 不改变消息正文、长度限制、发送条件、活动状态或连接状态。
- 不新增未读消息、回到底部按钮、表情、回复、已读回执或其他社交功能。
- 不复制微信品牌素材或追求像素级视觉复刻。

## 约束、风险与依赖

- 来消息左对齐，本人消息右对齐；两类消息都显示真实 `sender_username`，本人消息不得只显示“我”。
- 每条消息行展示发送者头像、用户名和消息气泡；当前用户身份提示继续在输入控件组正上方显示。
- 输入默认一行，最大可视高度三行（24–72px），超过三行后文本仍可编辑。
- 消息列表超过一屏时，只有追加前距内容底部不超过可视高度三分之一，实时新增消息才自动滚底。
- `before_id` 加载更早消息不得被当作实时新增消息或滚到底部。
- 头像只能来自现有 20 个本地 SVG 安全映射；不得接受外部路径、HTML 或不受信任资源。
- 活动数据继续按 `activity_id` 隔离，发送者身份继续按稳定活动用户 ID 判断。
- 保持 Vue 3、Vant 4、现有黑金视觉体系、移动端安全区和 600px 桌面预览限制。
- 当前 `ChatMessage` 没有 `sender_avatar_id`；不得改变聊天协议。若无法从现有数据得到真实头像，必须使用稳定、固定、本地且可复核的发送者 ID 映射或安全兜底，并在交接中说明。
- 风险包括短屏/键盘/安全区遮挡、长用户名破坏布局及实时追加与历史加载的滚动抖动。

依赖：活动壳提供 `activity`/`user`；`ActivityAvatar` 提供本地安全头像映射；现有消息稳定发送者 ID、用户名和实时/游标流程保持可用。

## 合理假设

- “微信风格”定义为消息头像、用户名、气泡和左右对齐的可观察布局，不要求复制品牌视觉。
- 用户名和头像要求适用于每条消息，包括本人消息；输入区上方的当前用户身份提示继续保留。
- 时间信息继续保留；历史加载继续维持视口内消息的相对位置。
- 在协议不变且消息没有头像字段时，前端使用稳定的发送者 ID 到本地头像的确定性映射；当前用户优先使用其已分配头像。

## 验收标准

### AC-001：输入区沉底与三行上限

**Given** 用户已进入活动聊天页，且消息列表可能需要滚动

**When** 页面首次渲染，用户输入文本并使文本达到一行、两行、三行及超过三行

**Then** 输入区保持在聊天可视区域底部、底部导航上方；输入默认一行，最大可视高度为三行；超过三行后高度不再增长，文本仍可编辑，发送按钮无遮挡。

### AC-002：接近底部时自动滚动

**Given** 消息列表超过一屏，且用户距内容底部不超过可视高度的三分之一

**When** 实时消息追加一条新消息

**Then** 新消息渲染完成后列表滚动到底部，最新消息可见。

**Given** 消息列表超过一屏，且用户距内容底部超过可视高度的三分之一

**When** 实时消息追加一条新消息

**Then** 不强制滚到底部，用户当前阅读位置保持不变。

### AC-003：当前用户身份提示

**Given** 当前活动用户包含用户名和头像标识

**When** 聊天页显示输入控件组

**Then** 输入控件组正上方显示当前用户名和对应头像；身份区独立于消息列表。

### AC-004：390×450 短屏底部布局

**Given** 浏览器视口为 390×450，页面存在消息、底部导航和安全区

**When** 聊天页首次渲染，或输入框增长至三行

**Then** 当前用户身份、输入框和发送按钮均完整位于视口内及底部导航上方；聊天消息区域承担剩余可滚动空间，不得被内容撑到视口外。

### AC-005：微信式消息行与左右气泡

**Given** 聊天列表中存在其他用户消息和当前用户消息

**When** 消息行渲染

**Then** 每条消息均显示发送者头像、真实用户名和消息气泡；其他用户消息整体左对齐，本人消息整体右对齐；本人消息用户名不得被“我”替代。

### AC-006：活动用户头像安全映射

**Given** 消息发送者存在有效的头像标识或稳定活动用户 ID

**When** 其消息行渲染

**Then** 显示固定本地 SVG 头像，同一发送者在列表中的头像保持一致；当前用户使用其活动头像。

**Given** 头像标识缺失、非法或无法匹配

**When** 消息行渲染

**Then** 使用固定本地安全兜底头像，不显示破损图片，不加载外部资源，不解析路径或 HTML；替代文本指向对应发送者。

### AC-007：聊天协议保持不变

**Given** 用户执行历史加载、实时接收、断线重连或发送消息

**When** 通过现有 HTTP/WebSocket 流程完成操作

**Then** HTTP 路径、`before_id`/`after_id` 游标、WebSocket 首帧 `auth`、`message.send`、`chat.ready`、`message.created`、`chat.error` 事件及现有消息字段保持不变，不新增或修改聊天 payload。

### AC-008：历史加载不跳到底部

**Given** 用户已在消息列表的任意阅读位置，且存在更早消息

**When** 用户触发加载更早消息

**Then** 更早消息显示在列表前部，加载前位于视口中的消息保持相对阅读位置，不滚到底部，也不被当作实时新消息处理。
