# TASK-v4：活动聊天室指定附属区域移除

## 状态

- 等级：T2
- 状态：已冻结
- 产品门禁：completed
- 输入版本：TASK-v2、DEVELOPMENT-HANDOFF-v2 及用户最新截图范围确认
- 旧版本处理：TASK-v2 的下游测试、审核和验收结论失效
- 待确认项：无

## 目标与用户场景

移除聊天子页中被用户标出的三个附属展示区域，降低无关视觉占用；保留消息识别、发送、实时接收、历史浏览、短屏布局和底部导航。

用户进入聊天页后，父级活动导航仍保留；聊天主体直接呈现消息列表，底部只保留输入框和发送按钮，不再显示活动标题、连接状态或当前用户身份提示。

## 范围

- 移除 `chat-header`：活动聊天室标题、活动名称和可发言标签。
- 移除 `chat-connection`：连接状态文本。
- 移除 `chat-composer-identity`：当前用户头像和用户名提示。
- 清理上述区域对应的高度、间距和无用样式，避免留下异常空白。
- 保留微信式消息行、发送者头像、真实用户名、时间、左右气泡、输入框、发送按钮、实时逻辑、条件滚动、历史锚点、390×450 布局和底部 Tabbar。
- 父级 `activity-nav` 保留。

## 非目标

- 不移除父级 `activity-nav` 或底部 Tabbar。
- 不修改 HTTP/WebSocket 协议、消息字段、头像资源、发送条件或活动状态逻辑。
- 不新增聊天功能或进行无关页面重构。

## 约束、风险与依赖

- 输入框默认一行，最大可视三行，超过三行仍可编辑；输入框和发送按钮始终位于 Tabbar 上方。
- 消息列表可滚动且用户距底部不超过可视高度三分之一时，实时消息自动滚底；远离底部时保持阅读位置。
- `before_id` 历史加载继续保持滚动锚点，不触发实时新增消息滚动。
- 消息行继续显示头像、真实 `sender_username`、时间和气泡；来消息左对齐，本人消息右对齐。
- 头像继续使用固定本地 SVG 映射，不加载外部资源、不解析路径或 HTML。
- 活动数据继续按 `activity_id` 隔离，发送者身份继续按稳定活动用户 ID 判断。
- 短屏、底部导航、安全区和移动键盘可能造成遮挡，需验证 390×450 与常规移动尺寸。
- 删除连接状态的展示不得删除连接状态对发送按钮可用性和重连逻辑的内部作用。

## 依赖

- 现有活动壳的 `activity-nav` 与底部 Tabbar。
- `ActivityAvatar`、本地头像映射及现有消息 HTTP/WebSocket/游标流程。

## 验收标准

### AC-001：输入框沉底与三行上限

**Given** 用户进入聊天页并存在底部 Tabbar

**When** 输入一行、两行、三行及超过三行文本

**Then** 输入框和发送按钮始终位于 Tabbar 上方；输入默认一行，最大可视三行，超过三行后仍可编辑且按钮无遮挡。

### AC-002：条件自动滚动

**Given** 消息列表可滚动且用户距底部不超过可视高度三分之一

**When** 实时追加消息

**Then** 列表滚动到底部并显示最新消息。

**Given** 用户距底部超过可视高度三分之一

**When** 实时追加消息

**Then** 不强制滚到底部，当前阅读位置保持不变。

### AC-003：指定区域不可见

**Given** 用户进入聊天页，活动状态和连接状态处于任意现有状态

**When** 页面渲染

**Then** `chat-header`、`chat-connection`、`chat-composer-identity` 均不可见；父级 `activity-nav` 仍存在。

### AC-004：390×450 短屏布局

**Given** 浏览器视口为 390×450

**When** 页面渲染或输入框增长至三行

**Then** 消息列表、输入框、发送按钮和底部 Tabbar 均可见，无控件遮挡或页面整体溢出。

### AC-005：微信式消息行

**Given** 列表中存在其他用户消息和当前用户消息

**When** 消息行渲染

**Then** 每条消息显示头像、真实用户名、时间和气泡；其他用户左对齐，本人右对齐，用户名不得替换为“我”。

### AC-006：头像安全映射

**Given** 消息发送者存在有效或无效头像标识

**When** 消息行渲染

**Then** 使用稳定的本地 SVG 头像或固定本地兜底头像，不加载外部资源、不解析路径或 HTML。

### AC-007：聊天协议不变

**Given** 用户执行历史加载、实时接收、断线重连或发送消息

**When** 现有 HTTP/WebSocket 流程执行

**Then** API 路径、`before_id`、`after_id`、`auth`、`message.send`、`chat.ready`、`message.created`、`chat.error` 及消息 payload 均保持不变。

### AC-008：历史加载锚点保持

**Given** 用户位于消息列表任意阅读位置且存在更早消息

**When** 加载更早消息

**Then** 更早消息出现在列表前部，原视口消息保持相对位置，不滚到底部，也不触发实时新增消息滚动。

### AC-009：无空白大间隙

**Given** 三个指定区域已移除

**When** 在常规移动尺寸及 390×450 下查看

**Then** 标题区、连接状态区和身份区不留下异常空白，消息列表与输入控件布局连续。

### AC-010：父级导航保留

**Given** 用户位于活动聊天路由

**When** 页面渲染或切换 Tab

**Then** `activity-nav` 和底部 Tabbar 均保持可见、可用及安全区适配。
