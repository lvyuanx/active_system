# TASK-v5：活动聊天室输入框默认高度校准

## 状态

- 等级：T2
- 状态：已冻结
- 产品门禁：completed（用户需求明确；产品角色线程两次未返回可用交接，主 Agent 依据已验证的 TASK-v4 和最新用户要求代拟）
- 输入版本：TASK-v4、DEVELOPMENT-HANDOFF-v4、用户最新明确要求
- 旧版本处理：TASK-v4 的测试、审核和验收结论对本版本输入框高度行为失效，其他行为纳入本版本回归
- 待确认项：无

## 目标与用户场景

用户进入活动聊天室后，输入框默认只占一行，并且默认状态的输入框外框与发送按钮等高；输入较长内容时输入框可自然增至最多三行，超过三行仍可继续编辑且在输入框内部滚动。输入区始终位于底部 Tabbar 上方，不影响既有聊天消息、头像、自动滚动和历史浏览行为。

## 范围

- 调整聊天输入框外层 Vant Field 的垂直内边距和内容对齐方式，使空输入/一行输入状态与发送按钮同高。
- 移除会在默认状态额外占用垂直空间的可见字数提示布局；保留 `maxlength=500` 限制。
- 保留 textarea 1–3 行自适应，超过三行后继续编辑并在控件内部滚动。
- 回归输入区沉底、条件自动滚底、微信式消息行、指定附属区域移除、父级导航和底部 Tabbar。

## 非目标

- 不修改 HTTP API、WebSocket URL、首帧 `auth`、发送/接收消息 payload 或消息字段。
- 不修改头像资源、头像安全映射、活动隔离、发送条件、重连和历史加载锚点逻辑。
- 不恢复聊天子页活动标题、连接状态或当前用户身份提示区域。
- 不进行与输入框高度无关的页面重构或视觉主题调整。

## 约束、风险与依赖

- 输入框和发送按钮均使用稳定触控高度；默认状态要求实际渲染外框高度相等，而非仅内容高度相等。
- textarea 单行内容高度为 24px，最大可视内容高度为 72px（三行）；外层边框可计入自身 1px 边框，不得因此遮挡发送按钮。
- 390×450 短屏和常规移动尺寸均需验证；输入区不能被底部 Tabbar 遮挡或推出视口。
- 移除字数提示只影响展示，不得移除 500 字输入限制。
- 项目使用 Vue 3 + Vant 4，聊天样式继续集中在 `chat.css`。

## 验收标准

### AC-001：默认一行输入框与发送按钮同高

**Given** 用户进入聊天页，输入区和底部 Tabbar 已渲染

**When** 输入框为空或仅包含一行文本

**Then** 输入框外框与发送按钮的实际渲染高度相等，内容垂直居中，二者整体位于 Tabbar 上方且无额外空白行。

### AC-002：输入框最多三行且超过三行仍可编辑

**Given** 用户在输入框中编辑文本

**When** 文本从一行增长到两行、三行及超过三行

**Then** 输入框随内容增长但最大可视内容高度为三行；超过三行后仍可编辑，文本在输入框内部滚动，发送按钮不被遮挡。

### AC-003：输入区沉底

**Given** 浏览器处于常规移动尺寸或 390×450 短屏

**When** 页面渲染或输入框增长

**Then** 输入框和发送按钮始终位于底部 Tabbar 上方，消息列表承担剩余可滚动空间，页面不发生整体溢出。

### AC-004：条件自动滚动

**Given** 消息列表可滚动且用户距底部不超过可视高度三分之一

**When** 实时追加消息

**Then** 列表滚动到底部并显示最新消息；用户远离底部时保持当前阅读位置。

### AC-005：指定附属区域不可见且无空白

**Given** 用户进入聊天页，活动状态和连接状态处于任意现有状态

**When** 页面渲染

**Then** `chat-header`、`chat-connection`、`chat-composer-identity` 均不可见，消息区与输入区布局连续；父级 `activity-nav` 仍存在。

### AC-006：微信式消息行

**Given** 列表中存在其他用户消息和当前用户消息

**When** 消息行渲染

**Then** 每条消息显示头像、真实用户名、时间和气泡；其他用户左对齐，本人右对齐，用户名不得替换为“我”。

### AC-007：头像安全映射

**Given** 消息发送者存在有效或无效头像标识

**When** 消息行渲染

**Then** 使用稳定的本地 SVG 头像或固定本地兜底头像，不加载外部资源、不解析路径或 HTML。

### AC-008：聊天协议不变

**Given** 用户执行历史加载、实时接收、断线重连或发送消息

**When** 现有 HTTP/WebSocket 流程执行

**Then** API 路径、`before_id`、`after_id`、`auth`、`message.send`、`chat.ready`、`message.created`、`chat.error` 及消息 payload 均保持不变。

### AC-009：历史加载锚点保持

**Given** 用户位于消息列表任意阅读位置且存在更早消息

**When** 加载更早消息

**Then** 更早消息出现在列表前部，原视口消息保持相对位置，不滚到底部，也不触发实时新增消息滚动。

### AC-010：父级导航和底部 Tabbar 保留

**Given** 用户位于活动聊天路由

**When** 页面渲染或切换 Tab

**Then** `activity-nav` 和底部 Tabbar 均保持可见、可用及安全区适配。

### AC-011：输入限制保留

**Given** 用户编辑消息

**When** 输入内容达到 500 个字符

**Then** 仍受 `maxlength=500` 限制；移除可见字数提示不得改变发送条件或消息 payload。
