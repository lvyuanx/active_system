# TASK-v1：优化抽奖大屏方屏、横屏与竖屏布局

## 任务属性

- 等级：T4
- 状态：已冻结
- 输入版本：`807bd2238db9b07e4fb860b1476960bd06216008`
- 变更性质：大屏端单模块响应式视觉行为调整，不改变接口、数据或抽奖协议

## 目标与用户场景

抽奖大屏需要覆盖方形屏、横屏和竖屏展示。方屏及横屏应持续使用主抽奖区与奖项进度板左右并列的布局；竖屏应将两块内容纵向组织，主抽奖区保持主要可视高度，奖项进度板在下方独立滚动，避免遮挡抽奖内容。

## 范围

- 调整 `apps/screen-web/src/components/lottery/LotteryScreen.css` 的响应式断点和方屏/横屏/竖屏布局规则。
- 调整竖屏下奖项进度板的高度、内边距、文字尺寸和滚动边界。
- 同步 `apps/screen-web/src/components/lottery/AGENTS.md`、`apps/screen-web/AGENTS.md` 及项目知识文件。
- 执行 screen-web 类型检查、生产构建、既有抽奖脚本测试和多视口浏览器复核。

## 非目标

- 不修改开奖 WebSocket、活动隔离、抽奖动画阶段和中奖数据结构。
- 不修改奖品板的奖项/奖品/中奖人数据分组逻辑。
- 不新增第三方布局依赖，不改变沉浸式抽奖阶段的全屏球体行为。

## 约束与风险

- 方屏按宽高比不低于 1:1 处理，不能因宽度小于 900px 而误切换为上下布局。
- 竖屏内容不得产生文档级横向或纵向滚动；奖项板内容较多时仅在板内滚动。
- 短高横屏仍保持左右布局，但需要保留主抽奖区和进度板的最小可视空间。
- 主要风险是极窄方屏、短高竖屏及长奖品名称的空间不足，需要浏览器视口和构建验证。

## 验收标准

### AC-001：方屏与横屏持续左右布局

**Given** 抽奖大屏处于普通非沉浸式状态
**When** 页面在 768×768 方屏、1024×768 横屏或 1280×720 横屏渲染
**Then** 主抽奖区和奖项进度板保持左右并列，奖项进度板位于主抽奖区右侧，不覆盖主抽奖区。

### AC-002：竖屏采用独立上下布局

**Given** 抽奖大屏处于普通非沉浸式状态
**When** 页面在 390×844 或 1080×1920 竖屏渲染
**Then** 主抽奖区位于上方并获得主要可视高度，奖项进度板位于下方；页面不出现文档级滚动，奖项较多时由奖项板自身滚动。

### AC-003：现有抽奖行为无回归

**Given** 本次只调整响应式布局与样式
**When** 执行 screen-web 类型检查、生产构建和既有抽奖脚本测试
**Then** 三项检查均通过，抽奖组件脚本和 WebSocket 协议未被修改。
