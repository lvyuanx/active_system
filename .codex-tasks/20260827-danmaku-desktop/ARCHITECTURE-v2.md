# 架构方案 v2：管理端真实聊天室弹幕测试

## 方案结论

复用现有聊天室的消息 service、活动状态校验、聊天室 manager 和弹幕 manager。新增按活动维护的进程内测试任务，
不新增用户端或投屏器协议字段：测试任务使用带“弹幕测试用户”标识的活动用户身份调用 `create_message`，
消息提交成功后分别广播完整 `message.created` 和四字段 `danmaku.message.created` 摘要。

## 模块边界与数据流

1. 管理端通过受超级管理员保护的状态、开启、关闭接口控制测试任务。
2. `danmaku.testing` 在单活动锁内准备 6 个稳定测试用户，使用活动 ID 和保留手机号标识复用身份。
3. 测试循环按轮询顺序调用 `chat.service.create_message`；该调用在同一事务中检查活动为 `open` 并写入
   `activity_chat_messages`，失败或活动变为只读时停止循环。
4. 成功写入后向 `chat_manager` 广播完整消息，向 `danmaku_manager` 调用现有摘要广播；两个事件共用同一
   `message_id`，历史接口从同一张表读取。
5. 应用 lifespan 结束时取消所有测试任务；停止接口取消指定活动任务并等待其退出。

## 接口与兼容性

- `GET /api/v1/admin/activities/{activity_id}/danmaku/test`：查询 `running` 和说明。
- `POST /api/v1/admin/activities/{activity_id}/danmaku/test/start`：仅 `open` 活动可启动，重复启动返回已运行状态。
- `POST /api/v1/admin/activities/{activity_id}/danmaku/test/stop`：停止指定活动，重复停止保持成功。
- 未授权仍由现有 `require_superuser` 拒绝；不存在的活动沿用 404；关闭/结束活动返回 409。
- 现有聊天室协议、弹幕 token、弹幕摘要、桌面工具和多屏渲染保持不变。

## 安全、并发和回滚

- 所有数据库查询和写入带 `activity_id`；测试任务不持有管理员或用户 JWT，不把测试凭证发送给客户端。
- 测试用户使用活动内保留手机号查找，名称冲突时返回 409，避免误复用普通用户身份。
- 每个活动最多一个 asyncio task；manager 锁保护任务替换，取消后等待退出，避免重复发送。
- 运行中活动变为只读时，下一次真实写入检查停止任务；停止或回滚只需关闭测试任务，不需要数据迁移。
- 测试消息是有意保留的运营演示数据，风险通过发送者名称和正文标识公开提示；多副本协调不在本版本范围。

## 测试重点

- 管理权限、活动隔离、open/closed/ended 状态、重复启停和任务清理。
- 两个不同测试用户产生的消息必须在聊天室完整事件和弹幕摘要中对应同一个消息 ID，并可从历史读回。
- 摘要字段白名单不变，普通聊天回归不变，管理端类型检查/构建通过。
- 既有 TASK-v1 的弹幕 token、配置、断线补齐、渲染、Electron 多屏和安装包回归继续执行。

## 任务图与工作包门禁

本版本使用 `TASKGRAPH-v2.json`，按产品 -> 架构 -> 开发 -> 测试 -> 审核 -> 验收 -> 清理拓扑执行。权限
不同的节点分批并设置屏障；本次共享 SQLite、主工作树、pnpm 缓存和测试服务不能安全命名空间隔离，写入路径
串行降级并记录 `UNISOLATED_RESOURCE`。工作包必须登记绝对路径、输入/HEAD 快照、读写范围、资源声明、
实际文件 SHA-256 和测试/审核证据；不创建提交，集成前执行受限补丁校验和主树漂移检查。

## 备选方案

- 不选本地前端预览：无法验证真实聊天室、持久化和弹幕通道，且与用户最终要求冲突。
- 不选为每个测试用户建立外部 WebSocket 客户端：会引入额外 JWT 和连接生命周期，不能比复用既有消息 service
  提供更强的真实链路保证。
- 不选新建测试消息表：会使聊天室历史与弹幕历史分叉，违背真实聊天室要求。
