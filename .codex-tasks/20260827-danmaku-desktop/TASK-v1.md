# TASK-v1: 活动弹幕桌面悬浮工具

## 目标

为活动系统交付活动级实时弹幕能力：管理员配置弹幕样式并管理一个当前 token；Windows Electron
桌面工具通过 token 连接，选择目标显示器后显示透明、置顶且鼠标穿透的实时弹幕。

## 范围

- 后端新增按 `activity_id` 隔离的弹幕配置、token、会话、历史补齐和 WebSocket 广播。
- 聊天消息持久化成功后继续按既有协议广播，同时向弹幕连接广播仅含正文的事件。
- 管理端增加弹幕配置和 token 管理界面。
- `screen-web` 提供可嵌入 Electron 的弹幕渲染层。
- 新增 Windows 优先的 Electron 应用、开发脚本和 NSIS 安装包构建链路。
- 更新受影响模块说明、README、MEMORY.md、WIKI.md 和 `.env.example`。

## 非目标

- 不修改用户端聊天界面和协议。
- 不实现多 token、多屏独立 token、敏感词审核、用户名展示、自定义字体或复杂动画编辑器。
- 不承诺 macOS 或 Linux 安装包。
- 不改变当前单进程内存广播的多副本限制。

## 已确认设计

- 每个活动只保留一个当前 token，管理员可重复查看和复制；重新生成立即使旧 token 失效。
- token 使用包含版本号的 HMAC 派生值；数据库不保存 token 明文。
- 弹幕仅显示聊天正文；首次连接不回放旧聊天，只从连接后实时消息开始显示。
- 管理端保存配置后，已连接弹幕工具通过 WebSocket 实时生效。
- 桌面工具启动时粘贴 token、可配置 API 地址、选择显示器；token 只在进程内保存。

## 验收标准

- AC-001：管理员只能读取和更新目标活动的弹幕配置；范围外数值或顶部/底部区域非法时返回 422。
- AC-002：同一活动重复读取得到同一当前 token；重新生成后 token 改变，旧 token 的 HTTP 和 WebSocket
  请求均被拒绝。
- AC-003：有效 token 能读取会话并完成弹幕 WebSocket 首帧认证；无效 token 收到结构化错误后关闭。
- AC-004：用户发言后，聊天室保持既有完整消息事件；弹幕连接只收到消息 ID、活动 ID、正文和创建时间。
- AC-005：管理员保存配置后，已连接弹幕工具立刻收到并应用配置变更，无需重连。
- AC-006：桌面工具可粘贴 token、选择显示器并仅显示启动后的消息。
- AC-007：弹幕窗口透明、无边框、置顶、不可聚焦且鼠标穿透，底层窗口仍可操作。
- AC-008：轨道、字体、不透明度、速度、显示区域、颜色会影响渲染；消息队列有界且溢出时丢弃最旧项。
- AC-009：断线自动重连并以 `after_id` 补齐运行期间漏掉的新消息；活动关闭或结束后不产生新弹幕。
- AC-010：后端测试、全部 Vue 应用构建、Electron 类型/主进程构建以及 Windows NSIS 安装包构建通过。

## 默认配置与约束

| 字段 | 默认值 | 约束 |
| --- | --- | --- |
| `track_count` | 6 | 1-12 |
| `font_size` | 36 | 16-96px |
| `opacity` | 0.9 | 0.1-1.0 |
| `duration_seconds` | 12 | 5-30 秒 |
| `display_top` | 10 | 0-80% |
| `display_bottom` | 90 | 20-100%，且大于 `display_top` |
| `text_color` | `#FFFFFF` | 六位十六进制颜色 |
