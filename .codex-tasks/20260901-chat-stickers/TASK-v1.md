# TASK-v1 聊天表情包端到端支持

## 任务状态

- 任务等级：T6
- 版本：TASK-v1
- 产品门禁：completed
- 待实施：后端迁移与媒体、管理端、用户端、大屏弹幕、测试和文档

## 目标

- 每个活动独立维护聊天表情包库。
- 管理员可以批量上传、查看、下架和恢复表情包。
- 活动用户可以在移动端点击表情并立即发送一条独立表情消息。
- 聊天历史、实时聊天和弹幕实时/HTTP 补齐均能展示图片及 GIF。
- 保持文本聊天、活动隔离、管理员权限、禁言、只读、停用用户和旧数据库兼容。

## 已确认范围与约束

- 资源按 `activity_id` 隔离；不建设全局共享表情库。
- 支持 PNG、JPG、WebP、GIF，单文件不超过 5 MiB；不支持视频。
- 管理端使用独立“聊天表情包”页面；多文件选择后逐个独立上传，失败项独立反馈。
- 名称默认取原始文件名去扩展名后的结果；首版不做拖拽排序。
- 移动端点击即发送 sticker-only 消息，不支持文字与表情混合。
- 表情消息保留兼容 `body`，值为 `[表情] 名称`；结构化字段供新客户端展示。
- 下架只从用户选择器隐藏；历史消息引用、图片资源和恢复能力必须保留。
- 表情发送沿用现有规则：活动为 `open`、用户 active 且未 muted；closed/ended 只读。
- 公开图片引用不携带管理员凭证，必须按活动和当前媒体版本校验。

## 用户场景

1. 管理员进入某活动的“聊天表情包”页面，选择多个文件，逐个上传并查看每项结果。
2. 管理员可以预览表情、下架不再使用的表情，并在需要时恢复。
3. 活动用户进入聊天，打开表情网格，点击一个表情立即发送。
4. 用户在历史或实时聊天中看到图片气泡；图片失败时看到 `[表情] 名称`。
5. 弹幕投屏器从实时 WebSocket 或 HTTP 补齐收到表情后，以图片/GIF 滚动，图片宽度参与碰撞。
6. 旧数据库升级后，历史文本消息和文本发送能力继续可用。

## 非目标

- 视频表情包。
- 文字与表情混合消息。
- 拖拽排序。
- 全局共享表情库。

## 风险与依赖

- 旧数据库缺少表情表和新增消息字段，迁移不得丢失文本历史。
- 软下架不能误删历史消息引用或图片资源。
- 公共图片接口必须严格绑定活动和媒体版本，不能暴露存储路径。
- WebSocket 和 HTTP 补齐必须使用一致的消息结构，避免遗漏或重复。
- GIF 和宽图会增加浏览器、大屏加载及碰撞测量压力。

依赖现有管理员/活动用户认证、活动状态、聊天 WebSocket/游标、弹幕 WebSocket/补齐、媒体校验和 `MEDIA_ROOT`。

## 验收标准

- **AC-001**：Given 两个活动分别存在表情包；When 查询任一活动的表情数据；Then 结果只能包含当前 `activity_id`，跨活动列表、消息和媒体访问均被拒绝。
- **AC-002**：Given 管理员选择多个文件；When 开始上传；Then 每个文件均有独立上传结果，不合并为一个表情或一个结果。
- **AC-003**：Given 文件为合法 PNG、JPG、WebP 或 GIF 且不超过 5 MiB；When 上传；Then 成功；格式不支持、真实格式不匹配、损坏或超限时失败且不产生可用记录。
- **AC-004**：Given 文件名为 `名称.扩展名`；When 未额外修改名称上传成功；Then 表情名称为 `名称`。
- **AC-005**：Given 活动已有表情；When 超级管理员列表、上传、软下架或恢复；Then 状态持久化且列表反映结果，已下架表情可以恢复。
- **AC-006**：Given 未认证用户、普通活动用户或非超级管理员；When 调用管理员表情能力；Then 请求被拒绝且不改变记录或媒体。
- **AC-007**：Given 活动用户已登录；When 加载启用表情及图片引用；Then 只返回当前活动的启用表情，版本化图片可无管理员凭证加载。
- **AC-008**：Given 旧数据库只有文本聊天表和消息；When 初始化升级；Then 新表及字段可用，旧文本历史和文本发送无数据丢失。
- **AC-009**：Given 活动 open、用户 active 且未 muted；When 点击启用表情；Then 现有聊天 WebSocket 持久化一条 sticker-only 消息，带表情类型、`sticker_id` 和 `[表情] 名称`，不混入文字草稿。
- **AC-010**：Given 活动 closed/ended、用户 muted/inactive 或跨活动发送；When 尝试发送表情；Then 沿用只读、禁言、未授权和隔离规则，失败不写入历史。
- **AC-011**：Given 聊天历史或实时消息含文本和表情；When 用户端展示；Then 文本仍为文本，表情为图片并保留发送者/时间，图片失败显示 `[表情] 名称`。
- **AC-012**：Given 表情已被历史消息引用；When 管理员下架并刷新用户端；Then 表情从选择器隐藏，历史图片和媒体仍可访问；恢复后重新出现在选择器。
- **AC-013**：Given 弹幕投屏器收到表情实时消息；When 处理 WebSocket；Then 图片/GIF 滚动，GIF 保持动画，图片展示宽度参与碰撞，失败回退文字。
- **AC-014**：Given 投屏器断线错过表情；When HTTP 补齐；Then 图片/GIF 滚动、宽度参与碰撞、失败回退文字且不重复展示。
- **AC-015**：Given 旧文本消息或旧文本弹幕消息；When 用户端或大屏处理；Then 继续按文本展示和滚动，无需表情记录或图片引用。

## 产品交接证据

- 当前聊天表为 `apps/backend/app/core/database.py` 中的 `activity_chat_messages`，消息模型和 WebSocket 只处理文本。
- 当前媒体服务 `apps/backend/app/modules/files/service.py` 只接受 JPG/JPEG、PNG、WebP，已有 5 MiB、真实 MIME、随机 key 和安全路径模式。
- 当前管理端无表情页面或侧栏入口；用户端 `chat.vue` 仅有文字气泡；大屏 `DanmakuOverlay.vue` 仅测量和滚动正文。
- 相关既有测试位于 `apps/backend/tests/test_chat.py`、`apps/backend/tests/test_chat_protocol.py` 和 `apps/screen-web/scripts/`。
