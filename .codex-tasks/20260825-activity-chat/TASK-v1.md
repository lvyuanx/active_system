# TASK-v1：活动独立聊天室与移动端三栏导航

## 状态

- 等级：T3
- 状态：已冻结
- 产品门禁：completed
- 待确认项：无

## 目标与用户场景

每场活动自动拥有一个按 `activity_id` 隔离的聊天室。所有已加入并登录该活动的用户均可进入；活动进行中
可发送持久化纯文本消息，未开始或已结束时只能查看历史消息。

移动端登录后固定提供“首页 / 聊天 / 我的”三个入口。“我的”展示当前活动基础身份并支持只退出当前活动。

## 范围

- 每场活动天然拥有聊天室，不增加管理端创建、开启或关闭聊天室的操作。
- 只有当前活动已注册且令牌有效的用户可以读取或发送消息。
- 消息长期持久化；正文去除首尾空白后长度为 1–500 字符。
- 历史默认加载最近 50 条、单次最多 100 条，支持向前分页和断线补拉；消息按 ID 正序展示并去重。
- `open` 状态允许读写；`closed`、`ended` 状态只允许读取。发送时以后端实时状态为准。
- 登录后的移动端路由为 `/activity/:activityId`、`/activity/:activityId/chat`、
  `/activity/:activityId/me`。
- 未登录时不显示底部导航；直接访问聊天或我的路由时显示当前活动登录门禁，登录后返回原请求页面。
- WebSocket 断线按 1、2、4、8、10 秒上限重连，恢复后补拉遗漏消息。
- “我的”展示活动名称、状态、活动用户 ID、用户名和加入时间；退出仅清除当前活动令牌。

## 公共接口行为

- 活动用户响应和 JWT 增加稳定活动用户 ID，响应增加加入时间。
- `GET /api/v1/activities/{activity_id}/chat/messages` 使用 Bearer 鉴权，支持 `limit` 以及互斥的
  `before_id`、`after_id`，返回 `{items, has_more}`。
- 消息包含 `message_id`、`activity_id`、发送者活动用户 ID、发送者用户名、正文和创建时间。
- `WS /api/v1/activities/{activity_id}/chat/ws` 连接后通过 `auth` 消息鉴权；成功返回 `chat.ready`；
  客户端发送 `message.send`；服务端持久化后广播 `message.created`；业务拒绝返回结构化 `chat.error`。
- 无效、过期或跨活动凭证必须拒绝，不能泄露其他活动消息。
- 旧令牌缺少活动用户 ID 时，仅在当前活动内用户名可唯一定位时兼容；不能唯一定位时要求重新登录。

## 非目标与约束

- 不支持图片、文件、语音、消息编辑、撤回、删除、审核、禁言、举报、未读角标和系统推送。
- 不修改管理端和大屏端功能，不增加聊天室独立开关。
- 首版不支持多后端实例跨进程广播。
- 保持 FastAPI 模块化单体、SQLite 和现有 Vant 黑金移动端视觉。
- Nginx `/api/` 代理需要支持 WebSocket Upgrade。
- 不降低当前后端测试和用户端 TypeScript 检查基线。

## 验收标准

- **AC-001**：Given 用户已登录活动，When 页面加载或切换入口，Then 底部固定显示“首页 / 聊天 / 我的”，
  当前项高亮，三个路由均可访问并支持直接刷新恢复；未登录时导航不可见。
- **AC-002**：Given 两名用户已加入同一 `open` 活动，When 任一用户发送合法文字，Then 双方实时看到包含
  正确发送者和时间的同一消息，刷新后仍可读取。
- **AC-003**：Given 用户持有活动 A 凭证，When 请求或连接活动 B 聊天室，Then 后端拒绝访问且不泄露
  活动 B 消息。
- **AC-004**：Given 活动为 `closed` 或 `ended`，When 用户进入聊天室，Then 可读历史但不能发送；即使
  客户端状态过期，后端仍拒绝新消息。
- **AC-005**：Given 连接断开期间产生新消息，When 网络恢复，Then 客户端自动重连、补齐遗漏消息且不
  重复显示。
- **AC-006**：Given 用户进入“我的”并退出，When 操作完成，Then 页面展示当前活动基础身份；当前活动要求
  重新登录，其他活动令牌不受影响。
- **AC-007**：Given 用户发送空白、超过 500 字符或非法协议内容，When 服务端处理，Then 消息不写入、
  不广播并返回明确错误；合法正文经去除首尾空白后保存。
- **AC-008**：Given 同活动存在重名用户，When 两人分别发送消息，Then 消息按稳定活动用户 ID 正确归属；
  旧令牌不能唯一定位时要求重新登录。
