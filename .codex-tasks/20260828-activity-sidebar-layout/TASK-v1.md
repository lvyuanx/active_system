# TASK-v1：修复活动管理侧栏被内容撑高

任务等级：T4（管理端单模块布局行为变更）

## 目标

修复活动管理页右侧长内容导致左侧活动菜单栏跟随页面高度拉伸的问题，保持桌面端侧栏独立于内容高度并可在页面滚动时持续可见。

## 范围

- 调整管理端全局活动壳样式中的桌面侧栏高度、网格对齐和滚动行为。
- 保留 800px 及以下断点的单列布局与自然高度侧栏。
- 同步管理端模块说明和项目知识文档。

## 非目标

- 不修改活动导航项、路由、接口或业务数据。
- 不改变右侧页面内容的滚动和横向溢出策略。

## 验收标准

- AC-001：给定桌面端活动管理页右侧内容高度超过视口，页面加载后左侧菜单栏高度保持在视口可用高度，不随右侧内容继续增长。
- AC-002：给定桌面端活动管理页发生纵向滚动，左侧菜单栏保持在视口内，菜单底部账户区域仍处于侧栏内部。
- AC-003：给定视口宽度不超过 800px，活动壳继续使用单列布局，侧栏恢复自然高度，不出现桌面端固定高度造成的额外滚动区域。
- AC-004：管理端类型检查、生产构建和 `git diff --check` 均通过。

## 约束

- 只修改管理端活动壳相关样式和对应文档。
- 保持现有桌面端 16px 外边距及移动端 10px 外边距。

## 风险与回滚

- 风险：视口高度较小时侧栏内容可能超过可用高度，因此桌面侧栏允许自身纵向滚动。
- 回滚：移除本任务在 `apps/admin-web/src/styles/index.css` 中新增的侧栏高度、粘性定位和移动端覆盖规则即可恢复原行为。
